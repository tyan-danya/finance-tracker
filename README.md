# Траты (SpendTracker)

Android-приложение для учёта личных расходов: быстрый ввод трат, дерево категорий,
статистика с графиками, фильтры по периодам и экспорт данных — в том числе готовый
отчёт, который можно отдать языковой модели с просьбой оптимизировать расходы.

Всё хранится локально на устройстве. Никаких аккаунтов, сети и аналитики.

## Возможности

- **Ввод траты**: сумма, категория, подкатегория, дата покупки (можно задним числом),
  способ оплаты, комментарий. Быстрые чипы «Сегодня / Вчера / Позавчера».
- **Категории**: 17 предзаполненных категорий и ~90 подкатегорий из коробки.
  Свои категории и подкатегории добавляются прямо из формы ввода.
  Используемые категории нельзя удалить — только скрыть, чтобы не рвать историю.
- **Статистика**: сумма за период, сравнение с прошлым периодом, средний чек,
  медиана, средние траты в день; кольцевая диаграмма и рейтинг по категориям;
  динамика по дням и по месяцам; разрез по подкатегориям, дням недели и способам оплаты;
  сводка «куда уходит больше всего».
- **Фильтры**: месяц, конкретный день, год, произвольный период, всё время.
- **Экспорт**: CSV (Excel), JSON (полные данные) и markdown-отчёт для ИИ-анализа.

## Установка APK

Готовый файл — в каталоге `dist/`. Скопируйте его на телефон и откройте;
Android спросит разрешение на установку из неизвестного источника — это ожидаемо,
приложение подписано локальным ключом, а не через Google Play.

## Сборка из исходников

Нужны JDK 17 и Android SDK (compileSdk 35, build-tools 35.0.0).

В этом окружении тулчейн развёрнут локально в `G:\toolchain`, и есть скрипт-обёртка,
который сам подставляет `JAVA_HOME` / `ANDROID_HOME`:

```bash
./build.ps1 test
```

```bash
./build.ps1 assembleRelease
```

Без обёртки — обычный Gradle wrapper, при заданных `JAVA_HOME` и `local.properties`:

```bash
./gradlew test assembleRelease
```

Release-сборка подписывается ключом из `keystore/spendtracker.jks`
(пароль хранилища и ключа — `spendtracker`, алиас — `spendtracker`).
Этот ключ пригоден только для личного использования: не публикуйте с ним приложение
в сторах и не переиспользуйте его в других проектах.

## Архитектура

```
domain/model      модели (ExpenseRecord, Category, Period, DateRange) — чистый Kotlin
domain/stats      StatsCalculator и модели агрегатов — чистый Kotlin, покрыт тестами
domain/MoneyFormat форматирование и парсинг сумм (всё в копейках, Long)
data/db           Room: сущности, DAO, база
data/             ExpenseRepository — единая точка доступа к данным, DefaultCategories
export/           CSV / JSON / markdown-отчёт, ExportManager (FileProvider + share)
ui/               Compose-экраны, графики на Canvas, тема
```

Ключевые решения:

- **Деньги — только `Long` в копейках.** Никаких `Double`, поэтому суммы не «плывут».
- **Даты — `LocalDate`, в базе хранятся как `epochDay`.** Нет таймзонных сдвигов,
  сортировка работает на уровне индекса.
- **Ручной DI** (`AppContainer`) вместо Hilt — компонентов мало, сборка быстрее.
- **Графики нарисованы вручную на Compose Canvas** — без сторонних чарт-библиотек,
  меньше зависимостей и полный контроль над темизацией.
- **Внешние ключи включены** (`PRAGMA foreign_keys = ON`): категория с тратами защищена
  от удаления (`RESTRICT`), удаление подкатегории обнуляет ссылку (`SET NULL`).

## Тесты

```bash
./build.ps1 test
```

Покрыты: `StatsCalculator` (агрегаты, периоды, zero-fill рядов, граничные даты),
`Period` / `DateRange`, `MoneyFormat` (парсинг пользовательского ввода),
экспортеры (экранирование CSV, валидность JSON, содержимое отчёта),
а также слой Room через Robolectric (репозиторий, ограничения внешних ключей, уникальность).
